# client

The app's logic without GPUI: what `shell`'s entities hold and decide, and the files that keep it. Data in, data out; the UI and the tasks stay in `shell`, whose run task awaits or drops `run::start`.

## Surface
- `Registry`: the sources, each added with its `Capabilities` (`add`, checked to be one source's) and removed (`remove`) while the app runs; `changes` tells each `Change`. A `Ref` goes to the source it names, an unknown one answers `Fresh(Err)` (a folder: an error status, a download: `Unsupported`); `download(url)` routes `<source>:...` like a `Ref`; `enter(game, process)` reaches the game's source's `Overlays` (blocking, `Unsupported` without one); `titled` lists the sources with `Titles`; `plays` (a source has games, trainers or accounts); `folders` and `stores` join every source's; `games` and `sign_in` are the first source's; `texts`, each source's catalogs as they are now; `has`, `name` (what the user calls a source, `Source::name`), `account_names` (that of each source with an account).
- `storage`: `Paths` names every app file and folder (`map_files`: a map's state folder, `MapFiles`; `update.json` is the shell's `Updates`', `window.json` its `placement`'); `Stored<T>`, `read` (the older per-map files), `disk`'s, re-exported; `migrate` (v1 files to v2, run by `app` before the window); `by_ref` (serde for a map keyed by `Ref`); `name` (an id as a file name).
- `media`: the media cache. `Media` (a cache folder per kind), the file per URL, `load`, `tile` (`Fetched`: ready, absent or retry) and `path` (blocking; disk first, never revalidated; a hit on a file older than a day refreshes its time for `sweep`), `cached` (the disk copy alone, its time left), `known_missing`, `forget_missing` (a map's absent tiles, by template), `steam_hero`; `limit` (`Kept`, `sweep`). An `http(s)://` URL comes from the CDN, any other through `Registry::download`; `NotFound` counts as a 404 and `Refused` as a 403. Absent is a 404, and for a tile a 403 or 410 too: kept as an empty file, never asked again; any other failure is asked again.
- `profile`: `Profiles` (`games.json`): a `GameProfile` by `GameId` (`overlay_in_game`: the game's own overlay mode, `None` the app's; `teleport_lift`: the map's TELEPORT HEIGHT), a `TrainerProfile` by the trainer's `Ref`; `favorites` (installed or not); `Collection` (`new`: the name rule, `NAME_LENGTH`), `Values`.
- `bindings`: `Store` (`hotkeys.json`, by trainer `Ref`), `Choice`, `rebind` with its `Clash` and `Resolution` (a held chord is bound only by `Keep` or `Take`), `shared` (the slots whose chord another slot holds too).
- `Load`: something that arrives after the window opens, or the `Failure` why it did not.
- `trainer`: `Sheet`, a trainer as the app holds it, with its `Ref`, its notes and folds by section id (`PINNED`, `NOTES` or a category), `step` (a hotkey's `Step`), `Span` (a slider), `settle` (a typed or a device's value as its control sets it), `sections` (the list's grouping, pins first), `initial`; `Shelf`, the sheets by game and the holds (a held game's newer copy waits), `outdate` (the language changed), `forget` (another trainer was chosen).
- `library`: `Game` (`install`: `None` for a catalog game, `installed`; `store`: the launcher, the record's store when not installed, `None` for a picked exe; `offer`, the trainer in use: `trainer_from`'s, the `Release` the user chose, else its own; `others`, the title's other releases, one per trainer), `GameId` (the first source's game `Ref` as text), `Library` (`catalog`, the source's games it was made of; `relink`; `land`, what a new list does to the open game (`Landing`); `trainer_records`, the trainer picker's order: the title's records, the other records of its install (`launchers::same_install`), then by likeness; `finds`, the search's rows: each listed game and a record per other title with a trainer, its Steam one first, none for a title with a record of a listed install: its names find that install's row), `rank` (the rows a query finds, best first), `by_name` (every list's order of names: a leading "the" skipped), `browse` (a catalog record as a `Game` not installed, with `stores`: a page per store of the title through `launchers::store_link`; blocking), `Release` (a record and its store, printed as is), `Support`, `Stamp` (the trainer in use, its revision, the build), `store_of`, `scan` (launchers joined with the catalog; their installs kept in `installs.json`), `kept` (the list from the last scan's installs, shown while `scan` runs; a kept picked exe counts only while it is still the picked one), `Picked` (`picked.json`), `Links` (`maps`: `map-links.json`, a title `Ref` per game; `trainers`: `trainer-links.json`, the record whose trainer a game uses; `set`, `clear`), `titles` (`matched`: a store id of the record or the active install, never a sibling release or a name; `likeness` over names, the pickers' order), `sources` (the source menu: `Entry`, and `Label`, data that shell words).
- `run`: `start(install, plan)` (one run; `Stage`: Preparing, Launching, WaitingForGame, Attaching), `start_game` (the game alone through its launcher, blocking), and the bookkeeping `opened`, `closed`.
- `api`: the remote panel's protocol, `View` out and `Command` in, `VERSION`; its TypeScript, `web/panel/src/api.ts`, is generated by its test (`IMPULSE_BLESS=1 cargo test -p client api`). `link()`: the server's `ServerSide` (`ask`, `feed`), the app's `Views` (the newest of each, a device's notes, revokes) and the `Ask`s it answers; `coalesce` (a burst's sets of one cheat as the last).
- `remote`: `Pairing` (the one-time code, `CODE_LIFE`, wrong tries locked) and `Devices` (`remote.json`: token hashes only, never a token; `has` says a device is still paired).
- `plugins`: `Plugins`, the plugins' life in the registry: `start` (the enabled ones, before the window), `list`, `inspect`, `install` (then added), `set_enabled` (added or removed), `remove` (removed first; the host may refuse: the plugin is added back and the failure returned), `set_value` (a running one added again: a replace); `Host`, its files, made by `app` over `plugins`. Every call blocks.
- `map`: `media` (the user's pins' pictures and clips, one folder `map_media` for every map, each named `<sha256>.<format>` by its first bytes: `keep`, `import` (a file read once, as it is copied; one kept already is left as it is), `jpeg` (a shot, quality 85), `read`, `path`, `is_clip`; PNG, JPEG, WebP, MP4 with a picture, WebM); `state` (`Saved`, the user's state of a map in a folder per map under `map_data`: `View`, this device's filters, layers and camera; found pins; hidden map pins (`hidden`, by id); the user's pins (`UserPin`, by id, its `media` by name; changed only through `PinEdit`, `move_pin`, which keeps a game position's height, `place_pin` (a typed game position) and `delete_pin`; `clone_pin` makes one with `Origin::Clone` that `stands_for` the map's pin it hides, whose FOUND is that one's: `found_of`) in the preset `mine`; `tally`, the counts by group (a hidden pin counts only while a copy stands in for it); changed in memory, written by `flush`; `View::resolve` turns region titles older builds saved into ids) and `heading`.

## Rules
- A plugin enters and leaves the registry only through `plugins::Plugins`, at start or on a command.
- `run::start` is the only code here that reaches `agent` (`settled`, `wait`), and names no source. Order: `Runner::prepare` first (a trainer that cannot run is refused before any game starts), then `agent::settled`, else `launchers::start` and `agent::wait`, then `attach` with the process exactly as found; blocking calls go through `unblock`.
- `Launch::Required`: a running game of any age is refused as `Restart` before `before_start`, a launch or an attach. Otherwise one still younger than `minimum_age` is waited for, never started a second time. `Launch::User` with none running is `ExternalLaunch` at once, as Wand's (`start_game` starts it alone, then LAUNCH attaches). Otherwise `before_start` comes before the launch, even one the launcher cannot make (the user starts the game then); its value lives until `start` ends or is dropped. The wait is the plan's `launch_within` (else 45 s) after a launch of ours, which gets the plan's `launch_arguments`, 180 s otherwise; a game not there in time is `NotStarted` after a launch of ours, else `NotRunning`. Dropping the future abandons the run; a trainer already inside ends with its session.
- A registration's streams end when it is removed or replaced: nothing late of it passes. Futures already given finish. The registry's lock is let go before a source is asked.
- No GPUI and no executor: a function here returns data; `scan` and `sweep` block and run off the UI thread; `run::start` is awaited by `shell`'s task, its blocking calls inside `unblock`.
- An app file is a `Stored<T>` opened from its `Paths` entry by its owner; a constructor takes `&Paths`, never the data folder. `edit` saves at once, blocking, in place and in order: tiny files only. Missing or damaged means the defaults, so a new field is `#[serde(default)]`. An object file carries `version: 2`; one without it, or that does not read, is never written (`Stored::load`).
- Keys are the source's ids: no code here splits a `Ref` or names a source. A change of a file's keys or shape is a new version with its step in `migrate`.
- An id reaches a file name only through `storage::name`; a new field of a map state file is `#[serde(default)]`.
- Map state merges record by record later (sync, imports): a found flag and a user's pin carry a `stamp` (ms, past the record's last), a delete is a tombstone, a pin id is random (taken over: from the older pin's content, so the same file gives the same ids anywhere), the taken-over records are stamped 0. A map's first load takes its older file (`map_state`, v2 then v1; one that is no map state is passed over) into the folder, staged and renamed whole; one not taken over, or there but unreadable, stays and the state is kept in memory only until the next load. The older files are never written or removed.
- Strings a frame prints are made once (`Game::name` is upper case, an `Arc<str>`); `shell` turns them into `SharedString` without a copy.
- A rebind answers a held chord with its `Clash`, checked against the bindings as they are at the write: `reserved` (the overlay's test merges modifier sides) is never bound; a slot of the same cheat holding it (`Chord::same_keys`) allows only `Take`, slots of other cheats `Keep` too (Wand fires every cheat bound to a chord); `Take` unbinds every holder.
- A protocol change bumps `api::VERSION` and regenerates the TypeScript. No source id or source name goes into a view: games are the bridge's handles, texts are worded.
- Stepping follows Wand's, except that `round_to` keeps the decimals of `min` too.
- A game on another record's trainer keeps its `GameId`, install and launcher; only the offer is that record's. A link to a record gone, without a trainer or its own means its own. Its build outside the trainer's list is `Unverified`, never `UpdatePending`: another store's builds are no update.
