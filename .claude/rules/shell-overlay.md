# shell overlay

The overlay slice, `overlay/`: `Layer` (window mode; `inside.rs` its IN-GAME side), `InGame` (`in_game.rs`), `Hud` (`hud.rs`), `Glance` (`glance.rs`), `Docks`, the overlay settings tab.

## Surface
- `Layer`: `toggle`, `leave`, `is_over`, `exclusive`, `hotkey`, `key(Slot)` (the extra hotkeys: minimap, zoom in, zoom out, pin here), setters. Emits `Playing` and `Pressed(Slot)`; tells `Input` its `input::Hud`. It observes `Settings` to hide the main window from capture.
- `InGame`: the one owner of the live run's canvas (`ready`, `size`, `layers`, `frames(layer, at, first)`), made by the page and given to `Layer` and, through `Hud`, to `Glance`; emits `InGameEvent` (`Canvas`: the current canvas's own event, `Gone`); `veil` hides the canvas's layers for a shot of the game (a `Veiled` guard of that canvas: the last one dropped, however the shot ended, shows each mirror still running at its last frame). Layer 0 is the HUD's, 1 `Glance`'s.
- `Glance`: the HUD minimap window; it observes `Settings` for capture exclusion and `InGame` for its layer.
- `Docks`, `Spec`: floating panels; each dock's `Spec` and `DOCKS` (the toolbar's order) live in `hud.rs`.
- `Hud`: the overlay's view, drawn by the page in place of itself while `Layer::is_over`. It makes the `Docks`, the dock's `Minimap`, the `Glance` and the `Warning` (`warning.rs`), and emits `Entered` when the window goes over a game.

## Rules
- Hotkey, foreground events, activation loss and UI asks are `Ask`s, run one at a time by the one `switch` task. Win32 calls that move, show, raise, lower or cloak Impulse's own window run there (or in `Glance`'s call task), never inside a GPUI update: they run GPUI's callbacks at once.
- The window stays cloaked until a frame of the new layout shows (`reveal`: two next-frame callbacks, 500 ms at most).
- `Playing` is emitted on change only. `Front` needs the foreground hook and is never set while over; going back to the game, `leave` settles it as soon as the mode turns (not after `reveal`), so `Glance` is up as the window goes. It reads the live pid from `Runs` and rechecks on every `RunEvent` but `Pressed`.
- The overlay goes over the live game only (in front, or brought forward from Impulse or the tray), never the desktop or another app. Its key and the extra hotkeys (minimap, zoom in, zoom out, pin here: `Slot`) are `keyhook::Key`s bound in `Input` as `Scope::Hud`: they act, and are hidden from the other apps, only while the live game is in front or the HUD is up. The zoom keys step the live map by `ZOOM_STEP` and do nothing without one.
- The overlay's and the extras' keys are bound by asking `Hotkeys` for a capture (`Target::Key`) and applying its outcome here: refused when another of them or a cheat's chord holds it. `Input::taken` keeps trainer chords off them.
- `Layer` tells `Input` its `input::Hud`: `Off` in the window, `Over` over the game (inside too until it takes keys), `Inside` once the layer takes input in the game (`typing`), cleared first on the way out. The same keys work in both modes: over the game the HUD has the focus; inside, `Input` sends each key it shows to `inside::type_keys`, which makes a keystroke of it in the game's layout (the vendored GPUI's `keystroke_in`) and dispatches it (`Window::dispatch_keystroke`, outside any update: the HUD's handlers read the layer). While typing, the window is held active (`Window::hold_active`, outside the layer's update: its observer hears it), so GPUI's inputs draw a caret and a capture or a question works. Its key-ups, IME and dead keys (dropped, never typed as their accent) do not come; a key queued outside a ready session, or typed in another app, is dropped. If the overlay over the game does not get the foreground, it leaves again.
- `exclusive` is read once per entry, before our window covers the game (`topmost::exclusive`: Windows answers for the whole session and a few seconds late, so only for the game in front). `Warning` asks on `Entered` unless `skip_exclusive_warning` (its DON'T SHOW AGAIN button sets it and closes; a switch in the OVERLAY tab turns the question back on), and the chip under the title banner stays while `exclusive` (the title and chip are taller than the top bar, so the group is top-aligned; the docks start below both); it hands the focus back to the `Hud` on `Closed`.
- `Glance` is a `PopUp` that never takes input: `focus: false`, `show: false`, `pass_through` before the first show. It is placed over the MINIMAP dock's minimap on the game's monitor, hidden (tiles dropped) when the live map is not placed, closed on `Playing::Idle` and on release. Its minimap keeps its tiles while the dock, the live map and the player are there, hidden or not (under the overlay too). It honours `hide_from_capture`.
- `InGame` asks for the canvas in the IN-GAME mode (the live game's own, `GameProfile::overlay_in_game`, else `Prefs::overlay_in_game`, the OVERLAY tab's MODE: IN-GAME until chosen, a mode saved before stays; either changing applies at once) with `Registry::enter` on `RunEvent::Live` or on switching to IN-GAME, off the UI thread; any `Err` is a quiet fallback to over the game. The first ask into a process waits (60 s at most, every 500 ms, until stale) for the window the overlay binds to once as it loads, the game's in front, else its first visible one (`topmost::first_window_of`), to be of a game's size: an Unreal game holds a hidden window in front while it loads, and a launch goes live there (DRG's cursors stuck). OVER THE GAME drops the canvas. A generation number bumps whenever the canvas is dropped (`Stopping`, `Ended`, another run, the stream's end) so a late answer is dropped; one ask at a time, and one that lands stale asks again for the run live then (an older ask landing later would take the game's canvas from the newer).
- Inside (`Mode::Over { inside: Some(away) }`): with a ready canvas of known size the toggle puts the main window, cloaked and never activated, frameless at the game's client origin with the canvas's size, right behind the game (GPUI's fullscreen first: it saves the rect for the way back), mirrored into layer 0 at (0, 0), interactive, with the global block. The game keeps the focus: foreground changes and alt-tab ask nothing; no exclusive warning. It leaves on the hotkey, Escape, the canvas's end (`Ask::Lost`) or Impulse's window coming in front (it stays in front); otherwise the window goes back behind the game as it was (`topmost::restore`'s `Away`). Layer 0's mouse input is posted to the window (`topmost::post_input`) and the window's cursor goes to the layer (`mirror_cursor`); GPUI reads the modifiers from `GetKeyState`, so a posted click carries none.
- `Glance` draws inside the game's frame when the canvas is `Ready`, else as the topmost window above: `mirror_frames` sends each frame at the dock's rect in the game's client area (`topmost::client_area`, read on the mirror's start, `Resized` and each `Playing` change, never per frame). The window stays topmost until a frame reached the canvas, then shows cloaked out of the topmost band; leaving the mode stops the mirror, hides the layer, then uncloaks. Mode, rect and visibility are placed together, so a mode switch at the same rect goes through. The frame callback only shows the layer.
- Entering the overlay closes the cheat list's menu and editor and the capture, selects the live game and emits `Entered`; the page closes its own parts on it (sources menu, picker, settings, log). The `Hud` draws the picker that the NO TRAINER card opens and takes the focus back when it closes. Escape closes the editor, then the menu, then leaves.
- The map in the MAP dock is the page's `MapView`, shown while `Maps::mapped`; the MINIMAP dock needs a record's map. Over a game the `Hud` opens and hides it (`place_map`) on each `Docks` and `Maps` change, so it does not depend on who hides it first (`MapView` hides itself when another game opens); the focus must not stay in a gone map. Out of the overlay the open map is the page's modal. The overlay tells `Maps` whether the MINIMAP dock is shown (`set_minimap`), at start and on each `Docks` change.
- PIN HERE: the `Hud` gives `Maps::pin_here` the shot to take (`shot.rs`), so the map never names the overlay: the live game's window in front, else its largest, through `capture` off the UI thread, 120 ms after the layers in its frame are veiled; the shot is a future holding the guard. Over the game nothing hides: a window capture holds only the game's window. The JPEG is `client::map::media::jpeg`'s.
- A new dock is a `Spec` static listed in `DOCKS` and an arm in `Hud::render`.
- Dock layout is one for all games, in `docks.json`, saved blocking on toggle, raise and release; a drag's bounds stay in its `Grab` until the release. A missing or damaged file means each `Spec`'s first bounds. `fit` keeps a dock on screen.

## Traps
- Windows refuses `SetForegroundWindow` to a process without the last input, and a hooked press gives none: `take_input` sends an empty input, then shares the front window's input with `AttachThreadInput` for the call.
- Raise only after GPUI's fullscreen switch, or the layer's rect is saved for the way back. Restore first (`topmost::restore`): a minimized or hidden window has no rect, and GPUI's fullscreen switch skips a hidden one. The switch is set, never toggled blind: a toggle against a window that is not where Impulse thinks leaves it fullscreen with dead caption buttons. `lower` never goes behind a topmost window, or it turns topmost.
- Do not read the foreground from a foreground event: it may be late; `switch` reads `topmost::foreground()` itself.
- `give_back` restores a minimized game with `ShowWindowAsync`: a hung game must not hang the caller.
- Windows skips a process's keyboard hook while it is in front if the process registered raw input: tao's raw input stays off (`DeviceEventFilter::Always` in `wand`'s webview).
- Over the game the window is transparent, and the kit's `Root` paints a background too: `see_through` clears both.
